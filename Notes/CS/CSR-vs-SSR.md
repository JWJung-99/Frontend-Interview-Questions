# CSR과 SSR의 차이점은?

## 📱 CSR

CSR(Client Side Rendering) 방식은 **브라우저가 서버로부터 비어있는 뼈대 HTML을 받아온 후**, 필요한 **JavaScript 번들을 다운로드하고 실행하여 동적으로 컨텐츠를 채우는 방식**입니다.

### CSR의 장점

- **인터렉션 향상**

  CSR 방식은 사용자 경험(UX) 측면에서 이점을 가지고 있습니다. 클라이언트 측에서 컨텐츠를 동적으로 생성하기 때문에 사용자의 행동에 따라 실시간으로 페이지 컨텐츠를 업데이트할 수 있습니다. 또한 서버로부터 모든 데이터를 받아 클라이언트 측에서 렌더링하기 때문에 초기 로딩 이후 페이지 이동 속도가 빠르다는 장점이 있습니다.

- **서버 부하 감소**

  CSR 방식은 클라이언트에서 컨텐츠를 렌더링하기 때문에 서버의 부하가 줄어들고 서버는 더 많은 요청을 처리할 수 있게 됩니다.

<br />

### CSR의 단점

- **초기 로딩 속도**

  CSR 방식은 필요한 HTML, CSS, JavaScript 등 모든 리소스를 받아와 실행해야 하므로 초기 로딩 시 느리며, 완료되기 전까지 화면이 비어 있을 수 있습니다.

- **자원 사용 증가**

  CSR 방식은 클라이언트에서 렌더링을 수행하기 때문에 사용자의 기기에 따라 성능 저하가 발생할 수 있습니다.

- **검색 엔진 최적화(SEO)**

  CSR 방식에서는 처음에 빈 HTML을 받아온 후 실시간으로 컨텐츠가 생성되기 때문에 검색 엔진이 페이지의 내용을 제대로 크롤링하기 어려워 SEO에 영향을 줄 수 있습니다. 하지만 현대 검색 엔진들의 JavaScript 해석 능력이 향상됨에 따라 이 역시 점차 개선되고 있으며, SPA 방식에서 `sitemap.xml`, `robots.txt`, `meta` 태그를 추가하고 `React-Helmet` 등의 라이브러리를 이용해 SEO를 개선하는 방법도 상당히 진전되었습니다.

<br />

## 💽 SSR

SSR(Server Side Rendering) 방식은 **서버에서 완성된 정적 HTML을 클라이언트에 전달**하는 방식입니다. 클라이언트에서는 해당 HTML을 파싱만 하여 화면에 그리게 됩니다.

Next.js 프레임워크에서는 SSR 방식으로 정적인 HTML을 전달해 초기 화면을 빠르게 렌더링한 후 이벤트 리스너 부착 등 JavaScript 작업을 수행하여 정적인 화면을 동적으로 전환하는 **hydration** 과정을 수행합니다.

### SSR의 장점

- **빠른 초기 로딩 속도**

  SSR 방식은 번들을 다운로드 받거나 번들을 실행하여 동적으로 화면을 그려야 할 필요가 없어 빠른 초기 로딩 속도를 경험할 수 있습니다.
  
- **검색 엔진 최적화(SEO)**

  SSR 방식은 화면이 동적으로 그려지는 CSR 방식에 비해 크롤러가 컨텐츠를 쉽게 인식하며, 초기 로딩 속도가 빨라 우선순위가 부여되어 상위에 노출될 가능성이 높습니다.

<br />

### SSR의 단점

- **사용자 경험**

  전통적인 SSR 방식에서는 클라이언트 사이드 라우팅이 불가능하여 빠르고 매끄러운 페이지 전환 경험을 제공하기 어렵습니다. Next.js를 활용하여 SSR 방식을 구현할 때에도 동적인 화면으로 전환하기 위해 hydration 과정을 거쳐야 하기 때문에 상호작용 초기화가 비교적 느립니다.

- **서버 부하 증가**

  SSR 방식에서 단순히 정적인 리소스를 내려주는 것이 아니라 요청 시마다 페이지를 동적으로 구성해서 내려주어야 하는 경우 WAS 서버 구동으로 인해 서버 부담과 비용이 증가할 수 있습니다.

<br />

## 🤝 적절한 사용

사용자 간의 상호작용이 잦고, 웹 페이지의 내용이 자주 바뀌며 초기 로딩 속도와 SEO 문제가 상대적으로 덜 중요한 경우, 사용자 경험을 중요시하는 경우 CSR 방식이 적합합니다.

사용자가 페이지를 내비게이션 할 때마다 빠른 로딩 속도가 필요하고, SEO 최적화가 중요한 요소의 경우 SSR 방식을 사용해 검색 엔진이 쉽게 크롤링할 수 있는 페이지를 생성하고 최적의 페이지 로딩 속도를 제공하는 것이 적합합니다.
