# 쿠키와 세션이란?

<br />

## 🤔 쿠키와 세션이 필요한 이유?

HTTP 프로토콜은 **비연결성(Connectionless)**, **무상태성(Stateless)** 의 특징을 가지기 때문에 서버는 클라이언트가 누구인지 매번 확인해야 합니다.

이 특성을 보완하기 위해 쿠키와 세션을 사용하게 됩니다.

<br />

## 🍪쿠키

### 쿠키

쿠키는 **클라이언트(브라우저)에 key-value 쌍으로 저장되는 작은 데이터 파일**입니다. 유효한 시간을 명시할 수 있으며, 유효 시간이 정해지면 브라우저가 종료되어도 인증이 유지된다는 특징이 있습니다. 서버에서 Response Header에 `Set-Cookie` 속성을 사용하면 클라이언트에 쿠키를 생성할 수 있으며, 사용자가 따로 요청하지 않아도 브라우저가 Request 시에 Request Header를 넣어서 자동으로 서버에 전송합니다.

<br />

### 쿠키의 구성 요소

- 이름: 각각의 쿠키를 구별하는 데 사용되는 이름
- 값: 쿠키의 이름과 관련된 값
- 유효시간: 쿠키의 유지 시간
- 도메인: 쿠키를 전송할 도메인
- 경로: 쿠키를 전송할 요청 경로

<br />

### 쿠키의 동작 방식

1. 클라이언트가 웹 페이지를 요청합니다.
2. 서버에서 쿠키를 생성합니다.
3. 서버는 HTTP 헤더에 쿠키를 포함시켜 응답합니다.
4. 클라이언트는 같은 서버로 요청 시 HTTP 헤더에 쿠키를 함께 보냅니다.
5. 서버는 쿠키를 읽고, 이전 상태 정보를 변경할 필요가 있을 때 쿠키를 업데이트하여 변경된 쿠키를 HTTP 헤더에 포함시켜 응답합니다.

<br />

### 쿠키의 사용 예시

- 웹사이트에서 아이디와 비밀번호를 저장하는 기능
- 쇼핑몰의 장바구니 기능
- 팝업에서 "오늘 하루 보지 않기" 기능

<br />

## 📟 세션

### 세션

세션은 쿠키를 기반으로 하고 있지만 사용자 정보 파일을 브라우저에 저장하는 쿠키와 달리 **사용자 정보 파일을 서버 측에서 관리한다는 특징**이 있습니다. 서버는 클라이언트를 구분하기 위해 세션 ID를 부여하며, 브라우저가 서버에 접속해서 브라우저를 종료할 때까지 인증 상태를 유지합니다. 사용자에 대한 정보를 서버에 두기 때문에 쿠키보다 보안에 좋지만, 사용자가 많아질수록 서버의 메모리를 많이 차지하게 되어 성능 저하가 발생할 수 있습니다.

<br />

### 세션의 동작 방식

1. 클라이언트가 서버에 접속 시 세션 ID를 발급 받습니다.
2. 클라이언트는 세션 ID를 쿠키에 저장해 보관합니다.
3. 클라이언트는 서버에 요청할 때 쿠키에 저장된 세션 ID를 서버에 전달합니다.
4. 서버는 세션 ID를 전달 받아 이를 바탕으로 세션에 있는 클라이언트 정보를 가져와 요청을 처리하고 클라이언트에게 응답합니다.

<br />

### 세션의 사용 예시

로그인 등 보안상 중요한 작업을 수행할 때 사용합니다.
