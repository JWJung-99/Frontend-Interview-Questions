# Vite를 사용하는 이유와 CRA의 한계?

<br />

## ⚡️ Vite

Vite는 빠르고 가벼운 Front-end 빌드 도구로, 빠른 개발 환경과 최적화된 번들링을 제공합니다. React 프로젝트에서 Vite를 사용하면 애플리케이션을 빠르게 실행하고 빌드할 수 있으며, HMR(Hot Module Replacement) 기능을 통해 개발 중 코드 변경 사항을 즉시 반영할 수 있습니다.

- 빠른 개발 서버: Vite는 모듈을 Native ESM(ECMAScript Modules) 형식으로 제공하며, **필요한 모듈만 즉시 로드**하여 빠른 개발 환경을 제공합니다.
- HMR(Hot Module Replacement): **코드 변경 사항을 즉시 반영**하여 브라우저 새로고침 없이도 UI를 업데이트할 수 있습니다.
- 빠른 번들링: ESbuild를 사용해 **번들링 속도를 크게 향상**시켰습니다.

<br />

### Vite를 사용하는 이유

Vite는 기존의 Create React App(CRA)에 비해 더 빠르고 가벼운 개발 환경을 제공하기 때문에 많은 개발자들이 Vite로 전환하고 있습니다. 특히 개발 서버를 시작할 때 전체 애플리케이션을 번들링하지 않고 필요한 모듈만 번들링하는 특성 덕분에 대규모 프로젝트에서 Vite는 첫 번째 빌드와 재빌드 속도가 상당히 빠릅니다.

<br />

## 🖼️ CRA

Create React App(CRA)는 React 프로젝트를 쉽게 시작할 수 있도록 해 주는 CLI 도구입니다. Webpack을 사용하여 번들링하고, Babel을 사용해 최신 JavaScript를 변환하여 복잡한 빌드 설정 없이 바로 React 프로젝트를 시작할 수 있게 도와줍니다.

<br />

### CRA의 주요 특징

- Webpack 기반: CRA는 내부적으로 Webpack을 사용해 애플리케이션을 번들링하고, Babel을 사용해 최신 JavaScript 문법을 변환합니다.
- React 개발 환경 제공: 기본적인 React 개발 환경과 빌드 도구를 포함하고 있어 별도의 설정 없이 React 앱을 바로 시작할 수 있습니다.

<br />

## ❓ 왜 Vite로 전환하는가?

CRA는 초기 프로젝트 설정과 빌드를 쉽게 할 수 있는 장점이 있지만, 프로젝트가 커지거나 요구사항이 복잡해질수록 **속도와 번들링 최적화 측면에서 한계**가 있습니다.

<br />

### CRA의 한계

- 느린 빌드 속도: CRA는 초기 빌드와 재빌드 시 Webpack을 사용하므로, 프로젝트가 커질수록 빌드 시간이 길어집니다.
- 느린 HMR: HMR이 느리고, 개발 중 변경사항을 적용하는 데 시간이 걸릴 수 있습니다.
- 성능 저하: 대규모 애플리케이션에서 Webpack의 빌드 시간이 매우 길어져서 개발 생산성이 떨어질 수 있습니다.

<br />

### Vite의 장점

- 더 빠른 개발 환경: ESM을 사용하여 초기 빌드 시간과 재빌드 시간이 CRA에 비해 훨씬 빠릅니다.
- 최적화된 번들링: ESbuild를 사용해 빠른 번들링 속도를 제공합니다.
- 유연한 설정: 커스터마이징이 쉽고, 다양한 플러그인 시스템을 제공합니다.

<br />

### CRA의 지원 중단

2025년 2월 14일, CRA의 새로운 앱 생성이 공식적으로 폐기되었습니다. 따라서 CRA는 더 이상 신규 프로젝트에 적합하지 않으며, Next.js, Vite, React Router 등 다른 프레임워크나 빌드 도구로 개발하는 것을 권장합니다. 이제 CRA는 유지보수 모드로 전환되며, React 19 지원 버전은 출시되었으나 신규 설치 시 경고 메시지를 표시해 더 이상 사용하지 않도록 권장합니다.
